## 통과로 주장할 수 없는 항목

1. 실제 Google 계정에 Blogger 임시글 전송: OAuth 키를 제공받지 못해 실제 Google API 통합 검증 안 함.
2. Blogger 테마 실제 가져오기·화면: 로컬 XML 파싱은 통과했지만 Blogger 실제 서비스 적용 여부는 미확인.
3. Chromium 브라우저 검증: 네트워크 정책으로 브라우저의 `http://127.0.0.1` 직접 이동은 차단되었습니다. 실제 HTTP 응답 HTML에 로컬 CSS·이미지·JS를 인라인해 **Chromium 오프라인 렌더링**한 4개 화면(PC/모바일 고객·관리자)을 확인했습니다. 4개 화면 모두 JS 오류 및 가로 오버플로 없음, 모바일 메뉴 토글 작동. 다만 실제 URL 탐색/클릭 전체 회귀 테스트와 Blogger 적용 검증은 아직 미완료입니다.
4. 항공·버스·숙박 예약/결제/정산: 실제 API와 계약 정보 없음.
5. 다수 직원 동시접속 장기 부하 시험, 개인정보 보호법 최종 법률 검토, 실 운영 외부 배포 보안 심사.

## 발견/개선 기록

- 초기 pytest 실행 바이너리의 경로 문제 → `python -m pytest`로 테스트 명령 명시.
- 분석 미들웨어의 세션 접근 순서 위험 → 별도 비식별 방문 쿠키 기반 집계로 교정.
- 회사 정보가 코드 고정이던 구조 → `/admin/settings` 실수정 및 DB 오버라이드 구현.
- 단순 메뉴허브에 그치던 초기 구조 → `module_registry`와 공개 라우트 활성/중지 로직 추가.
- 업체 등록증 원본과 상담 개인정보 → ZIP 공개 자산에서 제외.
