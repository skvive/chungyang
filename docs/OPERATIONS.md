2. 상담 담당자를 지정하고 연락 내용을 내부 메모에 적습니다. 고객의 건강/주민번호/민감정보를 메모에 수집하지 않습니다.

4. 기관 견학은 방문처 담당자 승인 확인, 참가자 특성, 안전·차량 배차·보험 등 필수사항을 확인합니다.
5. `/admin/products` 에서 상품 노출/숨김 관리. 실제 결제나 예약 확정 전 `가격`은 '맞춤 견적' 문구로 사용합니다.
6. `/admin/posts` 에서 공지·여행이야기 작성, 실제 고객 후기만 동의를 받아 등록합니다.
7. `/admin/media` 에서 AI 이미지 및 실사진을 WebP 업로드하고 경로 복사하여 제품/게시판 편집화면의 대표이미지에 붙여넣습니다.
8. `/admin/modules` 운영 중지 토글 확인, `/admin/analytics` 실측 방문자·상담 흐름 점검.

## 계정·안전

- 관리자 첫 개설은 `/setup`, 이후 자동 비활성화.
- 관리자/편집자/상담 담당자 권한이 다릅니다. 필요 이상의 관리자 계정을 만들지 않습니다.
- `data/cheongyangplus.db` · `data/session_secret` · `.env` 파일은 공개 웹 경로에 두지 말고 외부 저장소에 올리지 마세요.
- 개인정보 상담 CSV는 암호화된 업무 저장소에서만 보관·열람, 공유 시 반드시 비밀번호 보호.
- `scripts/backup.py` 로 SQLite 일관성 백업·업로드 이미지 ZIP을 생성합니다. `backups/`는 외부 저장소 복제 전 암호화하세요.
- 사업자 전화·주소 등은 `/admin/settings`에서 수정 가능. 구글 블로그는 별도 테마에도 고정 표기가 있으므로 함께 정정하세요.

## 외부 배포 시

- Windows 배치 실행은 **PC 내부 접속용**입니다. 사용자 PC 밖에서 접근시키려면 별도 서버/HTTPS/도메인 설정이 필요합니다.
- `CYPLUS_HOST=0.0.0.0`으로 아무 방화벽 없이 외부에 공개하지 마세요.
- 리버스 프록시 TLS 뒤에서 `CYPLUS_SECURE_COOKIE=1`, `CYPLUS_PUBLIC_URL=https://yourdomain` 설정하고 `data/`, `.env`, `backups/`, `tests/` 외부 접근 차단.
- 실제 예약대행·운송 인허가, 보험·고객 고지, 개인정보처리방침·약관·고객 동의 문구는 실제 사업 규정과 계약에 맞춰 별도로 점검하세요.

- 고객이 삭제를 요청하면 최고 관리자가 `/admin/leads`에서 해당 개인정보를 삭제하고, 기존 CSV·백업 복제본의 삭제 정책도 별도로 적용하세요.


## v1.1 후속업무·개인정보/계정 관리

- 신규 상담 도착 → 담당자 지정 → `후속업무·마감일`에서 방문처, 버스 수배, 계약 확인 등 실제 과제를 기록하고, 마감일까지 진행/완료 상태를 갱신합니다.
- 직원 퇴사나 권한 중단 시 `/admin/users`에서 **계정 중지**를 실행하세요. 모든 기존 세션은 다음 관리자 요청에서 거부됩니다. 비밀번호 변경 역시 기존 세션을 무효화합니다.
- `/admin/settings`에서 운영 책임자가 보유일수를 결정하더라도 **자동 정리되지 않습니다**. `python scripts/purge_expired.py`(기본 dry-run)로 대상 개수 확인 후 승인을 받아 `--execute`를 실행하세요. 정기 삭제 자동화와 복제 백업/CSV 완전 삭제는 별도 정책이 필요합니다.
- 여행상품을 모두 삭제해도 다음 실행에서 예시 데이터가 자동 복구되지 않습니다. 필요한 초기 데이터는 별도 백업에서 복원합니다.
- 외부 공개 전에 법률 검토를 거친 정식 개인정보처리방침으로 `/privacy` 초안을 교체하고, 동의 문구/쿠키 정책을 점검하세요.
